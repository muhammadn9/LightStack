Scope: worktree `.claude/worktrees/gym-today` (branch `claude/gym-redesign`), read-only. Compared against `origin/claude/production-readiness-hardening` (PR #76, unmerged, 53 files, never compiled, nothing deployed).

## Summary (most severe first)

1. **No account deletion on main** (App Store guideline 5.1.1(v)). Settings has Sign Out only. A full implementation (Settings > Delete account + `delete-account` edge function) exists on the hardening branch, not merged or deployed. Release blocker.
2. **No consent for sending personal data to Gemini, no privacy policy link, no privacy manifest on main (manifest FIXED on branch claude/audit-client-fixes; consent and policy link still open).** Profile, workouts, meal text and meal photos go to Google via ai-proxy with no consent screen. No `PrivacyInfo.xcprivacy` exists (the app uses UserDefaults, which needs a required-reason entry). The hardening branch adds consent gating, a policy row and a manifest template; the policy text is still a draft and `LSPrivacyPolicyURL` is not set. Release blocker.
3. **Database: views and grants (hardening migration not applied).** `user_streaks`, `recent_workouts_summary`, `month_plan_progress` are created without `security_invoker` in the schema file; every public table grants ALL to anon/authenticated; cross-user FK parents are unchecked. The branch's own audit says live was behind the repo (nutrition tables missing live). Fixed on the hardening branch, not applied. I could not verify live state read-only.
4. **ai-proxy has request-count limits only, no money limit.** 10/min and 100/day per user, but each request may carry a 3 MB image, google_search grounding and 8192 output tokens, and 5xx refunds give the slot back. A few accounts (sign-up is open and free) could run up the Gemini bill. Budgets/kill switch/ledger are on the hardening branch (not deployed). Add a Google Cloud budget alert regardless.
5. **FIXED on branch claude/audit-client-fixes (2026-11-16): Sign-out can fail silently, and offline sign-out is not possible.** `AuthService.signOut` only finishes locally on `sessionMissing`; any other error (offline) goes to `authErrorMessage`, which is only displayed by `LoginView`, so from Settings nothing happens. SUSPECTED.
6. **First-run flow is rough:** no explanation or permission context before sign-in, email sign-up stores the password in Keychain until verified, an unverified user must type nothing but tap "I've verified" and a hidden re-sign-in is used, and no terms/privacy text at the sign-in screen. Details below.
7. **FIXED on branch claude/audit-client-fixes (2026-11-16, recovery + quarantine + in-memory fallback): Core Data load failure is a `fatalError`** (`LocalStorageService.swift:46`): a failed lightweight migration or a corrupt store bricks the app on launch with no recovery path (users would have to delete the app and lose unsynced data). Models are versioned 1..11 with inferred mapping, which is the right setup; the risk is the no-recovery crash.
8. The sync layer is in much better shape than the 2026-10-13 baseline (see "Earlier findings"); remaining sync risks are small.

## 1. Data safety and sync

**1.1 Core Data load `fatalError`, no recovery** - High - CONFIRMED
- `Lightstack/Core/Services/LocalStorageService.swift:46`.
- Scenario: a store that fails to load (bad migration, full disk, corrupt file after a crash) crashes on every launch. Unsynced workouts are only in that store.
- Fix (M): on failure, move the store files aside (keep as `.corrupt-<date>`), create a fresh store, set a flag so the restore path runs, and show a message. Never delete silently.

**1.2 Sign-out with unsynced data** - Low (was P0) - CONFIRMED fixed on main
- `AppEnvironment.swift:488-499` keeps the queue; ops are owner-tagged. Residual: another account on the same device keeps the first account's rows in the same Core Data store (scoped by userId; privacy only). The hardening branch wipes local data on sign-out when nothing is queued.

**1.3 Sign-out failure invisible / offline** - Medium - SUSPECTED
- `AuthService.swift:415-430`; `authErrorMessage` shown only in `LoginView.swift:42`.
- Scenario: offline in Settings, tap Sign Out: nothing happens. Fix (S): on a network error still finish locally (clear local session) and sign out server-side later, or show the error in Settings.

**1.4 Local-only time-based cleanups can delete user data** - Medium - SUSPECTED
- `StaleWorkoutCleanup.swift`, `DuplicateWorkoutCleanup.swift`, `DataHygieneService.swift` (run after restore via `runDataHygieneIfNeeded`). Not read in detail. They delete workouts by heuristics; a wrong rule is silent data loss, and the deletes become tombstones that propagate to the cloud. Fix (M): review the rules against real data; log every deletion; add tests for the border cases (a workout started before midnight, empty-looking but real cardio sessions).

**1.5 Restore is a very large state machine** - Medium (risk) - SUSPECTED
- `SyncRestoreService.swift` (1034 lines), rules in docs/SYNC_DESIGN.md (tombstones win, local pending wins, first-reconciliation mode). Design reads sound. Known limit stated in the doc: repair works at workout level; partially present cloud workouts are not completed. Needs a real two-device test before launch (UI tests cover only a fake remote).

**1.6 Tombstones are fetched in full on every restore** - Low - CONFIRMED (by design)
- Fine at current scale; grows forever. Add cleanup/paging later (S-M).

**1.7 Session persistence** - OK. Supabase client persists the session in the Keychain; `SessionExpiry` keeps queued changes when the refresh token dies and shows a banner (`AppEnvironment.handleOutboxAuthFailure`).

## Current first-run and sign-in flow (as implemented)

Routing is in `Lightstack/App/RootView.swift` (order matters):
1. Launch: `AppEnvironment.checkExistingSession` (`AppEnvironment.swift:562`). If a Supabase session exists in the Keychain, the user is marked authenticated and the outbox flushes.
   - Local profile exists: skip onboarding, start background restore (at most every 6 h).
   - No local profile (new device / reinstall): `beginProfileRestore` shows `RestoreProgressView` while the cloud profile is looked up (15 s limit). Found: profile saved, history restored (up to 60 s), onboarding skipped. Not found: onboarding. Unreachable: "Couldn't reach your account" with Retry / Set up as new.
2. Not authenticated: `LoginView` ("Lightstack", "Your AI Strength Coach"): email + password card with Sign In / Sign Up toggle, "Forgot password?" (sends reset email, shows "Check your email..."), then "Sign in with Google" and Sign in with Apple. Errors arrive through `authErrorMessage` and are shown here only.
3. Email sign-up: `signUpWithEmail` -> `needsEmailVerification` -> `EmailVerificationView` (resend, "I've verified", back). The password is parked in the Keychain; "I've verified" signs in again with it. A sign-in with an unverified account signs back out and shows the same screen.
4. After sign-in (`authServiceDidSignIn`): same restore decision as step 1.
5. `OnboardingView` (3 steps): About you (name, goals) -> Split days (presets / custom) -> Equipment -> Finish. Finish re-checks the cloud for an existing profile and adopts it instead of overwriting.
6. `AppShellView` (Today / History / Progress / Profile tabs).
7. Sign-out (Settings): warns if unsynced; keeps the queue; returns to `LoginView`.

Concrete improvements:
- Add a short welcome/value screen (or at least a line under the logo) before the sign-in form, with Terms and Privacy links; put the policy links at the bottom of `LoginView` and in Settings.
- Make Apple and Google buttons equal prominence and put them above the email form; keep email as the secondary path.
- Replace the stored-password verification with the deep-link (PKCE) flow; auto-advance when the app returns from the email link; add "Use a different email".
- Show auth errors in a banner that works on any screen, not only `LoginView`.
- Add a "set new password" screen for the reset link if missing (2.5).
- Add a consent step in onboarding (AI processing, camera use) and a one-line explanation of why each permission is requested, before the system prompt.
- Make the restore screen explain what is happening, show counts ("restored 42 workouts"), and offer "Skip, keep going in the background" instead of a blocking wait.
- Add Delete account and Export data in Settings.
