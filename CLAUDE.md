# LightStack — Claude Code Rules

## After Every Coding Change

1. **Build first:**
   ```
   DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild build -project Lightstack.xcodeproj -scheme Lightstack -destination 'platform=iOS Simulator,name=iPhone 17 Pro,OS=latest' -quiet > /tmp/lightstack-build.log 2>&1; echo EXIT=$?
   grep -E "error:|BUILD FAILED" /tmp/lightstack-build.log | head -30
   ```
   Never pipe `xcodebuild` into `tail` before reading `$?` — `$?` would report `tail`'s status, so the build always looks like it passed.
2. If `EXIT` is not 0, or the grep prints anything → fix all errors before proceeding. Never commit broken code.
3. **Commit:** `git add -A && git commit -m "<clear description of what changed>"`
4. **Push:** `git push origin HEAD`

This applies after **EVERY task**, not just at the end of a session. No exceptions.

## Project File

The Xcode project is generated by XcodeGen from `project.yml`. Never hand-edit `Lightstack.xcodeproj/project.pbxproj`. After adding/removing any file, run `xcodegen generate`.

## Branch

Each change gets its own branch off the latest `main` (e.g. `claude/<short-topic>`), merged via PR.

## Code Style

- Swift only, no Objective-C
- SwiftUI views, no UIKit view controllers
- Follow existing AppTheme for all colors, fonts, and spacing
- No new third-party dependencies without explicit owner approval (GoogleSignIn SDK is approved)
- No force-unwraps — use guard/if-let

## General Preferences

- Responses should be concise. Don't spend extra tokens. Avoid heavy technical detail unless asked.
- "Done" means the feature works completely end to end, not just that it compiles.

## Agentic Workflow

1. **Opus researches and plans.** Opus may dispatch subagents for research/exploration only. Opus alone decides what is required and approves the plan. No implementation begins before plan approval.
2. **User approves the plan.** The plan is presented to the repo owner for explicit go-ahead.
3. **Sonnet subagents implement.** Once approved, work is split into independent workstreams dispatched to Sonnet subagents. Subagents must not commit or push — the orchestrator builds and commits centrally. Subagents that touch overlapping files run sequentially, not in parallel.
4. **User review.** The orchestrator builds, verifies EXIT=0, and brings the repo owner in to review before anything is pushed.
5. **Push + PR.** After owner approval, push and open a PR. Merge once the xcodebuild status check passes. There is no automated AI review on GitHub (Copilot review was turned off to save credits).
6. **Back to Opus.** Owner feedback on the PR returns to Opus, which triages it and re-enters the loop at step 1 for anything needing changes.

## Bug Workflow (UI tests on the simulator)

When the owner reports a bug, reproduce it with a UI test before fixing it:

1. **Reproduce.** Add a test to `LightstackUITests/` that performs the owner's exact steps, starting from `launchApp()` in `LightstackUITestCase` and using the shared helpers (`openTab`, `tap`, `type`, `shot`). Run it and confirm it **fails**, which proves the bug is reproduced. If it can't be reproduced on the simulator (device-only timing, haptics, camera, iOS-version differences), say so plainly and fall back to the crash log.
2. **Fix**, then run the test again and confirm it **passes**. Keep the test permanently as a regression guard.
3. **Before every TestFlight upload**, run the whole UI suite plus the unit tests.

**Test mode** (DEBUG builds only; Release/TestFlight contain none of it):
- `-uiTesting` signs in a fixed test user, uses a separate seeded store (`Lightstack-UITests.sqlite`), a fake AI provider and a separate session key.
- `-uiTestingReset` wipes and reseeds first.
- Real data and real Gemini calls are never touched.
- Pass `-appColorScheme light|dark` to force a theme.
- New views need stable `accessibilityIdentifier`s for tests to find them.

Run the UI suite and export screenshots:

```
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild test -project Lightstack.xcodeproj -scheme LightstackUITests -destination 'platform=iOS Simulator,name=iPhone 17 Pro,OS=latest' -resultBundlePath /tmp/ui.xcresult > /tmp/ui.log 2>&1; echo EXIT=$?
grep -E "Test Case.*(passed|failed)" /tmp/ui.log
xcrun xcresulttool export attachments --path /tmp/ui.xcresult --output-path /tmp/ui-shots
```

Add `-only-testing:LightstackUITests/<Class>/<test>` to run a single test. Delete any old `/tmp/ui.xcresult` first. Look at the exported screenshots to check visual bugs, and send relevant ones to the owner.

**Crash logs.** When the owner taps "Share" after a crash in TestFlight, fetch the symbolicated log. Run `source scripts/asc-config.sh`, then call `scripts/asc_api.py` on:
- `/v1/apps/$ASC_APP_ID/betaFeedbackCrashSubmissions` to list submissions
- `/v1/betaFeedbackCrashSubmissions/<id>/crashLog` to get one (`data.attributes.logText`)

The owner may also attach an `.ips` file directly.

## TestFlight

`scripts/testflight-release.sh --skip-tests`, after the unit and UI suites have passed. It bumps the build number, archives, uploads, waits for processing and adds the build to the tester group. Afterwards commit the bump: `Info.plist`, `project.yml`, `project.pbxproj`. Build numbers must never repeat. If `main` is behind the latest uploaded build, sync it before releasing.
